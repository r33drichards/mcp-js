# Railway deployment plan — not deployed

Status: budget cap and shutdown time pending from the user. No Railway connector or CLI is available in this environment; account/project authorization has not been verified. No billable service, project, token, domain or deployment was created. Existing production services remain untouched.

Railway maps Compose services to separate Railway services; it does not execute Compose directly. This generated full model has **37 services**, including optional Pi and the query network keeper. Do not upload the local Compose file and claim it will run unchanged. [Official Compose mapping](https://docs.railway.com/guides/docker-compose).

Proposed isolated topology, preserving the workload:

- New rehearsal-only project/environment after budget/lifetime approval, explicit service inventory and immutable image/build pins. Keep all Astronomy application services and collector/Prometheus/OpenSearch/Jaeger; keep added Loki/Grafana MCP.
- Three distinct mcp-js voter services, each with its own persistent sled/cache volume. One separate shared object service volume remains a single point of failure; do not advertise replicated blob durability.
- Co-locate the query runtime and upstream browser processes in a single purpose-built service to preserve loopback browser Host/Origin enforcement. Railway private DNS is not equivalent to Compose `network_mode: service:query-network`. Do not weaken the browser guard to make a service-name URL work.
- Co-locate the file publisher with Grafana so atomic file publication uses the same attached volume. The local cross-container shared volume is not a portable assumption. Alternatively implement authenticated pull/export into that service; do not substitute dashboard API writes silently. Runtime-mounted volume behavior is documented in [Railway volumes](https://docs.railway.com/volumes).
- Replace host Docker inspect/exec/kill operations with a narrowly scoped deployment adapter. The current controller is Linux-local only; it is **not** safe/functional to expose it directly on Railway. Lifecycle actions must allow only exact rehearsal node service IDs and need authorized Railway access. Pi/browser must never receive a broad Railway token or Docker socket.
- Use private service DNS and ports for MCP, Raft, blobs and telemetry. Railway private networking provides project-internal communication; it does not supply our application authentication. [Private networking](https://docs.railway.com/networking/private-networking).
- Public exposure should initially be static slides only. Interactive controller, browser desktop and Grafana require an explicitly approved authentication setup before a public domain is created. Local anonymous Viewer and unauthenticated demo storage are not suitable public endpoints. No secrets or access grants have been generated.
