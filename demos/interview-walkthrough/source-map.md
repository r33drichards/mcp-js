# Source map and rationale provenance

All mcp-js implementation links in architecture-reference.md and slides pin [base fe5b613](https://github.com/r33drichards/mcp-js/commit/fe5b613db0afcc9cf20d7ca1ef659c914a0b5008). Earlier COW reference is this exact commit. New demo integration is custom work on demo/interview-walkthrough, not claimed original engine behavior.

- Runtime: `server/src/engine/mod.rs`: `run_js_inner`, `build_fs_mount`, `execute_in_background`, `push_mount`; `server/src/cli.rs` storage defaults; `server/src/sandbox.rs` hardening boundaries.
- Virtual mount: `server/src/engine/fs_mount.rs`: `SessionMount`, `push`; directory tree/chunks in `fs_store.rs` and `fs_chunker.rs`. Bincode/BLAKE3 tree nodes, 64 KiB inline boundary, FastCDC chunks; no native host mount.
- Labels and merges: `server/src/engine/fs_labels.rs`; `ffi.rs` `fs_push`, `fs_reset`, `fs_merge`; `fs_gc.rs` collector reachability limitations. See reference for exact function paths/links and tests.
- History: [filesystem feature #169 / 4d6e446](https://github.com/r33drichards/mcp-js/commit/4d6e446bfe5c3fc884ead5796ebebdf6a9e0b3fb) documents recursive tree, streaming, copy-by-reference and CAS/rebase choices. This is documented project reasoning, not proof of Robert’s personal motivation. Local history also has learner support `f51140f`, shutdown RPC rejection `6193fef`, write forwarding `c269ff2`; inspect exact diff before attributing a rationale.
- Browser: [computer-use 63bab526 server.js](https://github.com/r33drichards/computer-use/blob/63bab526d2a999af969657f70a342dfebe1cbb63/images/browser/browser/server.js), adjacent `callers.js` localhost/Origin guard, `images/browser/flake.nix` desktop dependencies, `images/browser/Dockerfile`. Persistent tabs do not imply persistent JS isolates. Demo uses current engine, not production’s older pinned mcp-js image.
- Pi: [1.4.0 release](https://github.com/earendil-works/pi/releases/tag/v1.4.0), [MCP](https://pi.dev/docs/latest/mcp), [Codemode](https://pi.dev/docs/latest/codemode). `pi/paired-fork.ts` uses `session_before_fork`, `ctx.fork(...withSession)` and `session_start`; `pairing.py` is our custom binding journal. No claim that native Pi forks clone filesystems.
- Grafana MCP: [e97cd447 tools/loki.go](https://github.com/grafana/mcp-grafana/blob/e97cd4479eb40d25bc8d466db1651c29ce0c783e/tools/loki.go), `query_loki_logs`; official `query_prometheus` datasource routing. Generic run_panel_query rejects unsupported datasource types, so OpenSearch was not silently treated as supported.
- Astronomy: [2.1.3 commit](https://github.com/open-telemetry/opentelemetry-demo/commit/91356a39d5a0dc601317b55339b7abfafd91b481). [payment/charge.js](https://github.com/open-telemetry/opentelemetry-demo/blob/91356a39d5a0dc601317b55339b7abfafd91b481/src/payment/charge.js) checks paymentFailure; [payment/index.js](https://github.com/open-telemetry/opentelemetry-demo/blob/91356a39d5a0dc601317b55339b7abfafd91b481/src/payment/index.js) warns on caught error. `src/checkout/main.go` propagates payment errors. `src/otel-collector/otelcol-config.yml` sends OTLP logs to OpenSearch and span metrics to Prometheus. `src/grafana/provisioning/dashboards/demo/demo-dashboard.json` supplies verified metric names. Loki fanout is explicitly our adaptation; observed coverage remains pending.
